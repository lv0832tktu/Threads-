# まず投稿だけ始める

競合分析・RSS・週報は後回しで構いません。毎日08:00・19:00・22:00、就活・転職、AI、仕事術、お金、節約の通常文章21本を扱います。既存の画像・ツリー・分析機能は残っています。

## かんたん投稿準備

1. Windowsで `start_dashboard.bat` をダブルクリックします。キーを紛失している場合は、キー入力で**何も入力せずEnter**。投稿案の準備だけならキーは不要です。新キーを自動生成したり旧履歴を初期化したりはしません。
2. 「はじめに」の「かんたん投稿」を使います。翌週の開始日を選び、プロンプトをChatGPT Plusへコピーします。このチャットで作った下書きファイルを使っても構いません。
3. 返された21本JSONを貼り付けるか、JSONファイルを選んで取り込みます。全件未承認になり、日時が割り当てられます。重複ID・本文・予定日時は拒否します。
4. 本文・根拠・日時を確認します。必要なら本文を編集して「本文を保存」。選んだ全投稿の確認チェックを入れ、「まとめて承認」を押します。まだ予約・公開はしません。
5. 承認済み投稿を選んで「まとめて予約」。過去日時や重複予約、編集後の未承認投稿は拒否します。最後に「GitHub用の予約ファイルを作る」で4ファイルを保存します。

下書き・予約JSONはローカルの `private` に平文で置きます。公開リポジトリ・共有フォルダへ載せないでください。編集すると承認・予約が解除され、再確認が必要です。チェックした後に保存内容が変わった場合も、まとめて承認を拒否します。

## 自動公開は最後に設定する

実公開は既存のscheduled-posts.ymlで実装済みですが、この変更は公開スイッチを有効にしません。キー紛失対応と人間の承認が終わるまでは公開しません。

承認後に必要な設定は次のとおりです（今は変更しない）。

- [キー移行手順](state-key-migration.md)に従い、同じ新キーでGitHubとWindowsの本番履歴を保護する。本番切り替えは別途承認した作業が必要です。履歴を空にしません。
- Repository SecretsのTHREADS_SCHEDULE_JSON／_2／_3／_4に、書き出した4ファイルの内容を対応させる。未使用分も空JSONへ更新し、古い予約を残しません。THREADS_ACCESS_TOKENは既存のSecretを再利用します。
- config/automation.jsonとconfig/posting_schedule.jsonのauto_publish_enabledをtrueへ変更するPRを確認する。
- Repository VariablesのTHREADS_SCHEDULED_POSTS_ENABLED、THREADS_AUTO_PUBLISH_ENABLED、THREADS_PUBLISH_ENABLEDをtrueにする。その他の分析・検索・AI・RSSスイッチは不要です。
- 最初の承認済み1件で動作を確認してから継続運用する。公開結果不明・途中公開の履歴は削除せず照合します。

Actionsは15分おきに期限を過ぎた承認済み予約を確認します。GitHubの遅延により正確な分単位の公開は保証できません。二重投稿防止と永続化は既存の仕組みを使います。無料Actions枠を超える可能性があるため、利用量・予算を確認してから有効にしてください。

投稿文の作成はChatGPT Plusで週1回行います。このプログラムは有料AI APIを呼ばず、自動で毎日新しい文章を生成しません。予約がなければ投稿をスキップします。毎週の21本を取り込み・承認すれば、その週の公開は予約に従って進みます。
