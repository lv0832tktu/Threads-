# keyword_searchの手動接続テスト

このワークフローは手動実行のみです。schedule、投稿API、プロフィール探索、Insights取得、有料AI API呼び出し、Gitへの書き込みを含みません。
今回は実装と模擬APIテストだけを行い、実APIやActionsは実行していません。

## 検索語

`config/search-keywords.json` に指定された14分類204項目（203固有語）を登録しています。
AIツール、AI一般、AI用途、仕事効率化、仕事スキル、キャリア、家計、投資、税金、ポイ活、学び、掛け合わせ、フック語、収益導線を含みます。
「AI副業」は2分類に含まれます。`〇` を含む語も指定どおり保存し、ワイルドカードに変換しません。
「9割が知らない」「いいねで配布」は模倣を控える編集上の注意として保存しています。Metaによる個々の表示順位を保証する説明ではありません。

## 必要な設定

既存の `THREADS_ACCESS_TOKEN` Secretを使用します。値はコード・ログ・チャットに出しません。
keyword_searchには `threads_keyword_search`、基本読取には `threads_basic` をアプリ・認証画面で確認してください。
アプリ審査・アクセスレベル・個別トークンの実際の利用可否は接続テストで確認する必要があります。
前段の競合分析ガイドに公式サンプルと確認範囲を記載しています。

結果保護には既存設計の `THREADS_STATE_KEY` Secretも必要です。未登録なら安全な管理環境で鍵を用意し、Secretへ保存してください。
無料のcryptographyを使い、有料サービスは不要です。鍵がない/不正な場合はAPIに接続する前に停止します。
鍵の作り方と保管は [運用ガイド](automation-guide.md) を参照してください。鍵をチャットへ貼らないでください。
自動公開・定期分析のVariablesを有効にする必要はありません。

## GitHubでの手動実行（レビュー・マージ後）

1. Actions → **Threads keyword search connection check (manual only)** → Run workflowを開きます。
2. 最初は `group=ai_tools`, `offset=0`, `count=3`, `keyword`は空欄、`search_type=RECENT` のまま実行します。
3. ChatGPT、Claude、Geminiの3語だけを検索します。1回最大10語、1語最大10投稿、ページングなしです。
4. 特定の語だけ試すにはkeyword欄へカタログ内の語を入力します。例：`AI活用`、`S&P500`、`Claude Code`。
5. 別分類はgroupを変え、続きを調べる場合はゼロ始まりのoffsetを増やします。

204項目を1回で全検索しない設計です。検索枠・レート制限への負荷を抑えて順に接続確認します。
実行はGET /v1.0/keyword_searchだけです。アクセストークンはAuthorizationヘッダーに入れ、URLへ含めません。
エラーは固定の安全な理由として記録し、認証・権限・レート制限エラーで止めます。自動リトライはしません。
検索成功で0件の場合もあります。0件と権限エラーは区別して保存します。

## 結果を確認する

Actionsログは成功検索数・有効投稿数・エラー件数のみです。競合本文、トークン、投稿URL、検索結果の生JSONはログに表示しません。
実行ページの **Artifacts** から `encrypted-keyword-check-実行ID` をダウンロードします。保持は7日です。
Artifactsに含まれるのは暗号文 `search-check.enc` だけです。公開リポジトリのArtifactも第三者が読む可能性があるため、平文はアップロードしません。
APIの認証・権限エラーが起きた場合も、取得できた部分結果と安全なエラー理由を暗号化して保存します。
鍵検証やインストール等の事前失敗でファイルがない場合はArtifactを作りません。

ダウンロードした暗号文をローカルの `private/search-check.enc` へ置き、同じTHREADS_STATE_KEYを安全に注入した環境で復号します。

```bash
.venv-private/bin/python -m threads_publisher.search_check --decrypt
```

`private/search-check.md` に次を表示します。

- キーワード一致によるテーマ分類（厳密な意味理解ではありません）
- 文字数、フック形式
- APIが実際に返した投稿別いいね・返信・リポスト・引用
- 公式Threads投稿URL
- 検索ごとの成功/失敗と秘密を含まないエラー理由

投稿別反応数が取得できるとは保証しません。指定する基本フィールドでは数値が返らないことがあります。
未取得は「取得不可」と表示し、0に置き換えたり推測したりしません。プロフィール全体の反応数を投稿別値に代用しません。
本文は文字数・分類を計算した後に破棄し、保存・転載しません。URLの追跡クエリやフラグメントも保存しません。
テーマ・反応数は検索サンプルの観察に過ぎず、Threads全体の流行や表示順位を断定しません。

## 安全性・検証

ワークフロー権限はcontents: read、チェックアウトの認証情報を保持せず、標準ubuntu-latestランナーを使います。
認証情報付きリダイレクト・任意のpaging.next URL追跡を拒否します。出力先はignoredのprivate配下だけです。
有料AI APIは禁止のままです。既存の手動投稿と投稿履歴、定期公開の無効設定を変更しません。
GitHub Actionsは標準ランナーでも契約の無料枠を超えると料金が発生し得ます。実行前に支出上限を確認してください。

7件の追加オフラインテストで、全語句の登録、検索語選択・件数制限、GETのみ、URLエンコード、暗号化、権限・期限・レートエラー、空結果、重複、本文非保存、復号を検証しました。
既存69件を含む76件が成功し、全ワークフローのactionlintも成功しました。実APIの接続結果はまだ未検証です。
